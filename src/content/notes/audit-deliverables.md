공공 정보시스템 구축 사업을 처음 수주한 PM이 감리 통보를 받으면 대개 같은 질문을 합니다. "무슨 문서를 언제까지 내야 하나요?" 답은 고시에 적혀 있는데, 조문·가이드·표준 세 곳에 나뉘어 있어서 한 번에 읽기 어렵습니다. 이 글은 그 셋을 원문 그대로 한 자리에 모은 것입니다. 해석은 최소한으로 하고, 출처를 문장마다 붙였습니다.

## 먼저, 내 사업이 몇 단계 감리인지

「정보시스템 감리기준」(행정안전부고시 제2024-53호, 2024. 6. 27. 시행) 제3조 제1항입니다.

> 발주자는 감리법인으로 하여금 3단계감리를 하게 하여야 한다. 다만, 감리대상사업의 사업비가 20억원 미만이거나 사업기간이 6개월 미만인 경우 2단계감리를 하게 할 수 있다. 이 경우 발주자는 요구사항정의서의 과업내용 반영여부 등을 직접 점검하여야 한다.

3단계는 요구정의 · 설계 · 종료 세 회차, 2단계는 요구정의를 뺀 설계 · 종료 두 회차입니다. 사업비 5억 이상이면 감리 의무 대상이고(전자정부법 시행령 제71조), 그중 20억 미만은 대부분 2단계로 발주됩니다. 상주감리를 추가한 사업도 요구정의단계 감리를 생략합니다(같은 조 제2항). 즉 5억 이상 20억 미만 사업의 PM이 실제로 마주치는 감리는 대개 **설계단계 한 번과 종료단계 한 번**입니다.

2단계에서 빠진 요구정의 점검은 없어지는 것이 아니라 발주자 몫이 됩니다. 행안부 「정보시스템 감리 발주·관리 가이드」(2016. 12.)는 "발주자가 감리수행가이드에 따라 요구사항의 반영여부 등을 직접 점검하기 어려운 경우에는 가급적 요구정의단계 감리를 실시할 것을 권고"합니다.

## 감리 산출물 — 회차마다 사업자가 내는 문서

감리기준 제8조부터 제10조까지는 세 회차 모두 같은 구조입니다. 사업자가 "대비표"를 작성해 발주자 확인을 거쳐 감리법인에 감리 실시 전까지 제출하고, 감리법인이 그것을 기준으로 점검합니다. 대비표가 없으면 감리가 열리지 않습니다. 발주·관리 가이드는 "대비표는 감리기준 제8조부터 제10조까지에 따라 의무적으로 작성하도록 되어 있으며, 작성되지 않은 경우 감리수행이 어려울 수 있으므로 감리 착수 전에 사업자가 대비표를 충실히 작성하였는지 여부를 확인"하라고 발주자에게 적어 두었습니다.

| 회차 | 사업자가 내는 것 | 감리법인이 점검하는 것 (감리기준 조문) |
|---|---|---|
| 요구정의단계 (3단계 감리만) | 요구사항정의서 + **과업대비표** | "계약문서에서 정한 과업내용이 요구사항정의서에 적정하게 반영되어 있는지" (제8조 ①) |
| 설계단계 | 설계 산출물 + **요구사항추적표** (+ 검사기준서) | "설계 산출물이 과업내용을 적정하게 반영하고 있는지", "대비표가 세부 검사항목별로 적합·부적합 판정을 할 수 있도록 구체화되었는지" (제9조 ①) |
| 종료단계 | 최종 산출물 + **검사기준서** (요구사항추적표로 갈음 가능) | "세부 검사항목별 과업내용 이행여부"를 적합·부적합으로 (제10조 ①) |

세 문서의 정의는 NIA 「SW 사업자를 위한 정보시스템 감리 준비 및 대응 가이드」(2023. 2.) §1.4에 있습니다.

- **과업대비표** — 사업자가 제안요청서, 제안서, 기술협상서, 사업수행계획서, 요구사항정의서에 기술된 과업 항목을 대비하여 **누락 여부**를 확인할 수 있도록 작성한 문서.
- **요구사항추적표** — 요구사항정의서에 기록된 개별 요구사항이 프로젝트 진행 단계마다 적정하게 반영되었는지를 추적할 수 있도록 작성한 문서. 사업자가 요구분석단계에 최초 작성하며 각 사업 진행 단계마다 갱신.
- **검사기준서** — 세부 과업항목별로 이행여부를 점검하기 위한 문서로 요구사항추적표를 활용하거나 별도 작성. "요구사항, 검사항목, 검사기준을 포함"해야 하고, 기능 요구사항의 검사기준은 테스트 시나리오로 구체화.

같은 가이드는 둘을 묶어 "대비표"라고 부릅니다. 감리기준 조문의 "대비표"가 어느 문서인지는 회차가 정합니다.

## 요구사항정의서 · 과업대비표 · 요구사항추적표 · 검사기준서 양식 — 예시 컬럼

양식은 고시에 없습니다. 감리 수행 가이드(NIA, 2022. 2.)와 TTA 표준 TTAK.KO-11.0162(CBD 소프트웨어 산출물 개발 지침)의 예시가 사실상 표준이고, 2023 사업자 가이드가 그것을 옮겨 실었습니다. 예시 컬럼을 그대로 적습니다.

**요구사항정의서 (예시 1, TTAK.KO-11.0162)**
요구사항 ID / 요구사항명 / 구분(기능·비기능) / 요구사항 설명 / 출처 / 제약사항 / 중요도 / 해결방안 / 검수기준 / 비고

**과업대비표 (예시, 감리 수행 가이드 2022)**
제안요청서(제안요청ID · 요구사항 내용) / 제안서 / 기술협상 / 사업수행계획서 / 요구사항정의서

각 칸에는 그 문서의 절 번호나 ID를 적습니다. 예시 행은 `SFR-003 → III.2. 로그인 관리 및 이용로그 분석 → 없음 → 3.나. 국민홈페이지분야 → REQ-FR-003-01` 식입니다.

**요구사항추적표 (예시, TTAK.KO-11.0162)**

| 단계 | 컬럼 |
|---|---|
| 분석 | 요구사항 ID · 요구사항명 · 유스케이스 ID |
| 설계 | 화면 ID · 컴포넌트 ID |
| 구현 | 프로그램 ID |
| 시험 | 단위시험 ID · 통합시험 시나리오 ID |

**검사기준서 (예시, 감리 수행 가이드 2022)**
기능: 요구사항 ID / 요구사항명 / 세부 검사항목(화면 · 프로그램) / 검사기준(테스트케이스) / 비고
비기능: 요구사항 ID / 요구사항명 / 세부 검사항목 / 검사기준 / 비고

주의할 점 하나. 이 컬럼 예시는 2022년판 수행 가이드에서 처음 실렸습니다. 2013년판(v2.0)에는 정의만 있고 예시 표가 없습니다. 그 10년 동안은 "식별자를 이용하여 과업내용을 요구사항으로 추적할 수 있도록"이라는 원칙만 있었기 때문에, 회사마다 방법론 템플릿의 양식이 다릅니다. 발주기관이나 감리법인이 지정 양식을 주면 그것이 우선입니다.

제안요청서 쪽도 확인해 두면 좋습니다. 공공 SW 사업 제안요청서는 요구사항을 SFR · PER · DAR · PMR 같은 고유번호 표로 냅니다(요구사항 고유번호 / 요구사항 명칭 / 정의 / 세부내용 / 산출정보). 여러 제안요청서가 프로젝트관리 요구사항(PMR) 항목에 "각 요구사항이 분석·설계·시험 단계 산출물에 반영됐는지 확인할 수 있도록 관리(요구사항 추적)하여야 함, 산출정보: 요구사항추적표"라고 적어 둡니다. 추적표는 감리기준의 의무이면서 동시에 그 사업의 계약 산출물입니다.

## 감리 점검항목 — 감리원은 대비표에서 무엇을 보나

감리 수행 가이드 2022 설계단계 절(36~44쪽)이 감리원의 점검 순서를 적어 두었습니다. 세 겹입니다.

1. **형식 요건.** "개별 요구사항에 대한 설계내용을 반영하고 있는 설계 산출물 정보가 누락되지 않았는지, 각 요구사항 ID에 대응하는 세부 검사항목과 검사기준이 빠짐없이 작성되었는지."
2. **추적성.** "대비표에 명시된 요구사항이 요구정의 단계 대비표와 비교하여 특별한 사유 없이 누락되지 않았는지, 설계단계에서 추가 또는 제외된 요구사항이 관련 설계 산출물에 반영되어 추적이 가능한지."
3. **설계 산출물 내용 적정성.** 요구사항 관점과 산출물 관점 둘로 나눠 본 뒤 개선권고를 씁니다. 작성 사례 원문은 "요구사항1에 대한 설계서 반영 여부를 점검한 결과 \~의 반영이 미흡하므로 개선이 필요함"입니다.

국가직무능력표준(NCS) 「IT감리」 능력단위(2013 v1)는 같은 내용을 감리원의 수행준거로 적었습니다. 설계단계 요소 2.2가 "확인된 요구사항추적표에 따라 추적항목으로 기술된 설계산출물들의 추적 가능 여부를 점검할 수 있다"입니다. 표에 적힌 화면 ID와 프로그램 ID가 실제 화면정의서·프로그램명세서에 있고 내용이 맞는지를 감리원이 직접 따라간다는 뜻입니다. 같은 표준은 요구사항 한 줄의 단위도 정합니다. "각 요구사항은 개별적으로 설계 적정성과 과업 이행 여부 확인이 가능하며 중복되지 않아야 한다", "개별 요구사항은 기능점수(FP) 단위(크기)로 작성을 권장".

개선권고의 결과는 필수 · 협의 · 권고 세 유형과 장기·단기 두 시점으로 나옵니다. 종료단계의 과업이행 판정은 적합 · 부적합 · 점검제외 셋이고, 부적합에는 반드시 관련 증빙이 붙습니다. 시정조치는 조치완료 · 조치중 · 반영불가로 보고하고, 반영불가에는 발주자 확인 문서가 필요합니다.

## 감리 준비 순서 — 계약 직후 · 설계 완료 전 · 종료 전

사업자 가이드(2023)가 권하는 순서를 회차별로 옮기면 이렇습니다.

- **계약 직후**: 제안요청서의 요구사항 고유번호를 기준으로 요구사항정의서를 만들고, 그 ID를 이후 모든 산출물이 물려받게 합니다. 과업대비표는 이때 함께 만듭니다. 변경은 요구사항정의서에 명시적으로 남깁니다.
- **설계 완료 전**: 요구사항추적표의 설계 열(유스케이스 · 화면 · 컴포넌트 · 프로그램)을 채우고, 검사기준서를 이 시점에 함께 만듭니다. 가이드는 "설계 단계에서 검사기준서를 작성하지 못한 경우에는 요구사항추적표에 변경내용을 갱신하여 관리하고 종료단계 감리 이전에 검사기준서로 활용할 수 있음"이라고 열어 두었지만, 종료단계 감리원은 검사기준서로 적부를 판정하므로 미리 만드는 쪽이 안전합니다.
- **종료 전**: 단위·통합 테스트를 돌려 검사기준서의 완료여부를 채우고, 비기능 요구사항은 이행 결과 산출물(성능시험결과서 등)을 증빙으로 붙입니다.
