## 응답 속도는 숫자, 관련성은 신뢰

검색이 0.05초 만에 끝나도 첫 화면에 엉뚱한 결과가 올라오면 사용자는 검색창을 다시 쓰지 않습니다. 검색 관련성(search relevance)은 **사용자가 찾으려던 것과 검색 결과가 얼마나 맞아떨어지는가**를 말합니다. 단순히 단어가 들어 있느냐가 아니라, 의도에 맞는 문서가 위쪽에 올라오느냐의 문제입니다.

이 글은 관련성의 기본 개념을 정리하면서, Elasticsearch·OpenSearch로 한국어 검색을 운영하는 팀이 실제로 손댈 수 있는 지점을 함께 짚습니다.

## 한국어 검색에서 관련성이 무너지는 다섯 지점

영어는 띄어쓰기가 곧 단어 경계지만, 한국어는 조사·어미가 붙고 복합명사가 길게 이어집니다. 그래서 형태소 분석기(Elasticsearch·OpenSearch에서는 보통 Nori)가 문장을 어떻게 자르느냐가 검색 품질의 출발점입니다. 현장에서 자주 보는 실패 유형은 다음과 같습니다.

| 유형 | 예시 | 증상 |
| --- | --- | --- |
| 미등록 신조어·고유명사 | '당근마켓', '숏폼', 신제품명 | 엉뚱하게 쪼개져 다른 문서와 섞이거나 아예 안 잡힘 |
| 복합명사 분해 | '공공데이터포털' | 너무 잘게 쪼개면 정밀도 하락, 통째로 두면 '데이터포털' 검색에서 누락 |
| 띄어쓰기 변이 | '검색 엔진' / '검색엔진' | 같은 뜻인데 결과가 달라짐 |
| 외래어·표기 변이 | '엘라스틱서치' / 'Elasticsearch' / 'ES' | 사용자가 쓰는 말과 문서가 쓰는 말이 어긋남 |
| 동음이의·짧은 질의 | '배', '사과' | 의도를 알 수 없어 상위 결과가 뒤섞임 |

이 문제들은 랭킹 알고리즘을 아무리 다듬어도 해결되지 않습니다. 색인 단계에서 토큰이 잘못 만들어지면 점수 계산에 쓸 재료부터 틀어지기 때문입니다. 한국어 검색 튜닝의 첫 작업이 대개 **사용자 사전과 동의어 정비**인 이유입니다.

## Elasticsearch·OpenSearch는 점수를 이렇게 매긴다

두 엔진 모두 기본 관련성 점수(`_score`)를 **BM25**로 계산합니다. 원리는 세 가지로 요약됩니다.

- **단어 빈도**: 질의어가 문서에 자주 나올수록 점수가 오르지만, 일정 횟수를 넘으면 증가폭이 줄어듭니다.
- **희소성(IDF)**: 전체 문서에 드물게 나오는 단어일수록 무게가 큽니다. 한국어에서 '것', '등' 같은 토큰이 걸러지지 않으면 이 계산이 흐려집니다.
- **필드 길이**: 짧은 필드(제목)에서 맞은 단어가 긴 본문에서 맞은 단어보다 유리합니다.

여기에 운영자가 얹을 수 있는 장치가 있습니다.

- **필드 가중치**: `multi_match`에서 `title^3, body` 처럼 제목 일치를 더 높게 봅니다.
- **구문·근접 일치**: `match_phrase`나 `slop`으로 단어가 붙어 나온 문서를 끌어올립니다. 복합명사가 많은 한국어에서 효과가 큽니다.
- **비즈니스 신호**: `function_score`로 최신성, 판매량, 평점, 재고 여부 같은 값을 점수에 섞습니다.
- **의미 검색**: 임베딩 벡터의 kNN 검색을 BM25와 함께 돌리고 RRF 등으로 순위를 합치는 하이브리드 검색. '저렴한 노트북'과 '가성비 랩탑'처럼 단어가 겹치지 않는 질의를 보완합니다.

주의할 점은 `_score`가 **질의마다 상대적인 값**이라는 것입니다. 점수 12점이 좋은지 나쁜지는 그 자체로 의미가 없고, 같은 질의 안에서의 순서만 의미가 있습니다. 그래서 관련성은 점수가 아니라 별도의 지표로 재야 합니다.

## 관련성을 숫자로 재는 법

측정의 출발점은 **판정셋**(judgment list)입니다. 실제 검색 로그에서 자주 쓰이는 질의 50\~200개를 뽑고, 각 질의에 대해 '이 문서는 정답/부분 정답/무관'을 사람이 표시해 둔 목록입니다. 이것만 있으면 아래 지표를 반복해서 계산할 수 있습니다.

| 지표 | 무엇을 보나 | 언제 유용한가 |
| --- | --- | --- |
| Precision@K | 상위 K개 중 정답 비율 | 첫 화면 품질이 중요한 상품·문서 검색 |
| Recall | 존재하는 정답 중 찾아낸 비율 | 누락이 치명적인 법률·조달·감사 문서 검색 |
| MRR | 첫 번째 정답이 몇 위에 나왔나 | 정답이 하나뿐인 질의(특정 공고, 특정 제품) |
| nDCG@K | 정답이 위쪽에 올바른 순서로 놓였나 | 정답 등급이 여러 단계인 일반 검색 |
| 제로 결과율 | 결과가 0건인 질의 비율 | 사전·동의어 누락을 가장 빨리 드러냄 |

Elasticsearch와 OpenSearch에는 판정셋으로 이런 지표를 계산하는 **Ranking Evaluation API**(`_rank_eval`)가 들어 있어, 설정을 바꿀 때마다 같은 질의 세트로 점수를 비교할 수 있습니다.

판정셋과 함께 실사용 신호도 봅니다. 클릭률, 검색 후 질의를 고쳐 다시 검색하는 비율, 첫 클릭 순위 같은 로그 지표입니다. 사용자가 늘 1위를 건너뛰고 3위를 누른다면 순위 설계가 틀렸다는 신호입니다.

## 한국어 검색 관련성을 올리는 여섯 가지 실무

### 1. Nori 사용자 사전으로 토큰부터 바로잡기

서비스에서 중요한 고유명사, 상품명, 업계 용어를 사용자 사전에 등록합니다. 복합명사는 `원어 + 분해형`으로 등록하면 통째 검색과 부분 검색을 함께 살릴 수 있습니다.

```json
"tokenizer": {
  "ko_tokenizer": {
    "type": "nori_tokenizer",
    "decompound_mode": "mixed",
    "user_dictionary_rules": [
      "공공데이터포털 공공 데이터 포털",
      "숏폼",
      "시즐론"
    ]
  }
}
```

핵심은 **어떤 단어를 넣을지 찾는 일**입니다. 시즐론은 실제 문서를 분석해 쪼개지거나 사라지는 어절을 통계로 뽑아 사전 후보를 만들고, 판정셋으로 전후를 잰 뒤 반영합니다([공고명 183,240건으로 잰 기록](/notes/korean-tokenizer/)). 사용자 사전은 색인 시점 분석에 영향을 주므로, 바꿀 때는 새 인덱스로 재색인하고 alias를 전환하는 절차가 함께 필요합니다.

### 2. 동의어는 검색 시점에 적용하기

'엘라스틱서치, Elasticsearch, ES'처럼 같은 대상을 가리키는 말을 묶습니다. `synonym_graph` 필터를 **검색 분석기**에만 두고 `updateable: true`로 설정하면, 재색인 없이 분석기 재로드만으로 동의어를 갱신할 수 있습니다.

```json
"filter": {
  "ko_synonym": {
    "type": "synonym_graph",
    "synonyms_path": "analysis/synonyms.txt",
    "updateable": true
  }
}
```

### 3. 품사·불용어로 잡음 걷어내기

`nori_part_of_speech` 필터로 조사·어미 같은 품사를 걸러내고, 서비스 특성상 의미 없는 단어(예: 공고 검색의 '공고', '입찰')는 불용어 후보로 검토합니다. 다만 지나치게 걸러내면 구문 검색이 깨지므로 판정셋으로 전후를 비교한 뒤 확정합니다.

### 4. 필드 가중치 정하기

제목, 요약, 본문, 태그의 중요도는 서비스마다 다릅니다. 제목 일치를 우대하는 것이 일반적이지만, 제목이 짧고 형식적인 공공 문서처럼 본문이 더 중요한 경우도 있습니다. 가중치는 감이 아니라 판정셋 점수로 정합니다.

### 5. 비즈니스 신호 섞기

재고 있는 상품, 최근 기사, 마감 전 공고처럼 '지금 보여줘야 할 것'을 `function_score`로 반영합니다. 신호가 텍스트 관련성을 덮어버리지 않도록 `boost_mode`와 가중치 상한을 함께 정합니다.

### 6. 단어가 안 겹치는 질의는 하이브리드로 보완하기

사전과 동의어로 메우기 어려운 '의미는 같은데 표현이 다른' 질의는 벡터 검색을 함께 돌려 보완합니다. 단, 한국어 하이브리드 검색도 BM25 쪽 토큰이 건강해야 결과가 안정적이므로, 1\~3번이 먼저입니다.

## 바꾼 것은 반드시 검증한다

관련성 튜닝에서 가장 흔한 실수는 '몇 개 검색해 보니 좋아졌다'로 끝내는 것입니다. 한 질의를 고치면 다른 질의가 나빠지는 일이 흔하기 때문에, 변경은 항상 아래 순서로 확인합니다.

1. **기준선 측정**: 현재 설정으로 판정셋 지표(nDCG@10, 제로 결과율 등)를 기록합니다.
2. **한 번에 하나씩 변경**: 사전, 동의어, 가중치를 동시에 바꾸면 무엇이 효과였는지 알 수 없습니다.
3. **오프라인 비교**: 같은 판정셋으로 `_rank_eval`을 다시 돌려 전후를 비교하고, 나빠진 질의를 따로 확인합니다.
4. **실사용 비교**: 트래픽이 충분하면 A/B로 나눠 클릭률과 재검색 비율을 봅니다. 트래픽이 적다면 내부 사용자 검수로 대신합니다.
5. **판정셋 갱신**: 새로 등장한 질의와 실패 사례를 판정셋에 추가해 다음 사이클의 기준으로 삼습니다.

검색 품질은 한 번 맞추고 끝나는 설정이 아닙니다. 새 상품, 새 용어, 새 사용자 습관이 계속 들어오므로, 이 사이클을 분기마다라도 돌리는 팀과 그렇지 않은 팀의 차이는 시간이 갈수록 벌어집니다.

## 시즐론 검색 품질 진단

한국어 검색의 관련성은 랭킹 공식보다 **토큰, 사전, 측정 체계**에서 먼저 결정됩니다. 검색 결과가 이상하다는 말은 많은데 무엇부터 고쳐야 할지 모르겠다면, 대개 이 세 가지 중 하나가 비어 있습니다.

시즐론은 Elasticsearch·OpenSearch를 쓰는 팀을 대상으로 **검색 품질 진단**을 고정가로 제공합니다. 직접 운영하는 클러스터, AWS OpenSearch Service, Elastic Cloud 환경 모두 다룹니다.

- 현재 분석기 설정과 매핑 점검
- 실제 검색어 기준 형태소 분절·미등록어 분석
- 사용자 사전·동의어·불용어 개선안
- 판정셋 기반 측정 체계와 개선 전후 비교

실패하는 검색어 20\~50개를 보내 주시면, 영업일 1일 안에 Nori 기본 설정 기준 형태소 분절·미등록어 진단 결과 1쪽을 먼저 보내 드립니다. [무료 스캔 신청](/contact/?service=search&scan=1#form)
